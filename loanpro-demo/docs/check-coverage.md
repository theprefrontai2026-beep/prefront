# LoanPro — check coverage matrix

Generated by `docs/gen_coverage.py` from `scenarios.py` and `app_tools.INTENTS`. Do not edit by hand.

Every check in `prefront-check-families.md` maps to at least one session in the catalogue and to the span attributes an out-of-band evaluator reads to detect it. **Scripted** sessions guarantee the finding; **LLM** sessions rely on gpt-4o-mini actually misbehaving under the prompt, which it does reliably but not always.

## Trace shape (one session = one trace when run from the orchestrator)

```
session <SCENARIO-ID>   CHAIN  loanpro-orchestrator   session.id user.id app.user.role app.channel
                                                      scenario.id scenario.family scenario.checks app.variant
└─ turn <n>             AGENT  loanpro-ungoverned     session.id user.id app.user.role app.channel app.turn
   │                                                  app.turn.mode=llm|replay input.value=user msg output.value=answer
   │                                                  app.tools_called app.variant app.model
   ├─ ChatCompletion    LLM    loanpro-ungoverned     llm.model_name llm.input_messages.* llm.output_messages.*
   │                                                  llm.tools.* session.id user.id (app.replay=true when scripted)
   └─ tool <name>       TOOL   loanpro-app-mcp        session.id user.id app.user.role app.channel
                                                      tool.name app.intent app.side_effect app.catalog app.trust
                                                      input.value=args output.value=result incl. rows (≤20)
                                                      app.row_count app.columns status=ERROR on failure
```

A deployment that drives the agent directly (no orchestrator) produces one trace per turn; `session.id` is on every span, so `GET /oob/sessions/{id}` still assembles it.
